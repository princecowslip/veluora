# Search and Discovery

## Search pipeline

1. Parse query.
2. Validate fields and ranges.
3. Resolve source scope.
4. Check local block rules.
5. Build local query.
6. Translate external query per connector.
7. Execute concurrently within rate limits.
8. Stream result groups.
9. Normalize metadata.
10. Apply local post-filters.
11. Collapse duplicates and variants.
12. Rank and paginate.
13. Record search history only when permitted by privacy settings.

## Query grammar

Examples:

```text
type:video duration:<20m
creator:"Example Creator"
source:local favorite:true
tag:example -tag:blocked
pages:20..100 language:en
(term-a OR term-b) type:image
```

## Search history

Controls:

- Disabled
- Session only
- Fixed retention
- Unlimited until cleared

Private sessions never persist search history.

## Ranking

Possible signals:

- Exact title match
- Creator match
- Tag overlap
- User-selected sort
- Source relevance score
- Local favorite and collection presence
- Recently added
- Unviewed status

Do not silently combine source popularity into a single opaque score. Provide sort modes and an explanation panel.

## Duplicate collapsing

Group likely equivalents using:

- Same source item
- Canonical URL
- Cryptographic hash
- Perceptual image hash
- Video or audio fingerprint
- Similar title, creator, duration, and dimensions

Display a preferred variant while allowing expansion.

Preferred variant rules may prioritize:

1. Local verified file
2. User-designated preferred source
3. Higher quality
4. Non-expiring access
5. Authorized download
6. Stable canonical reference

## Discovery pages

Possible source-provided routes:

- Recent
- Popular
- Categories
- Creators
- Series
- Tags

The UI must label these as source-provided and avoid suggesting the ranking is generated by the application.

## Saved searches

Saved search fields:

- Name
- Query
- Source scope
- Sort
- View mode
- Thumbnail privacy
- Notification setting, disabled by default

## Smart collections

A smart collection is a saved local query evaluated against the local library. External results should not appear unless explicitly designed as a dynamic source view.

## Privacy constraints

Never send these to connectors:

- Private notes
- Local ratings
- Private tags
- Collection names
- Local folder names
- Other source credentials
- Full browsing history
